Стек технологий:
    Язык: Python 3.12+ (управление зависимостями через uv).
    Framework: FastAPI (асинхронный).
    Databases: 1.  PostgreSQL (asyncpg): Реляционное ядро, данные о посещаемости (партиционирование по неделям).
    2.  Redis: Кэширование профилей студентов (Hash-сеты) и JWT-черный список.
    3.  Neo4j: Граф связей (Студент-Группа-Курс-Лекция).
    4.  MongoDB: Иерархия (Университет -> Институт -> Кафедра).
    5.  OpenSearch: Полнотекстовый поиск по контенту лекций.
Infrastructure: Docker Compose, API Gateway (проверка JWT).

1. Общие правила архитектуры (Shared Core)

Все микросервисы и сидер должны использовать общий пакет shared/ (монорепозиторий).

    shared/database.py: Синглтоны асинхронных коннекторов для всех 5 БД.

    shared/schemas.py: Общие Pydantic-модели (Student, Lecture, и т.д.).

    shared/utils.py: Логика валидации JWT.

2. Инструкция по генератору (Seeder)

Задача: Полная очистка и заполнение всех БД (~1000 записей на сущность).

    Консистентность: UUID объекта (например, Студента) должен быть идентичен во всех базах (Postgres, Redis, Neo4j).

    Производительность: Использовать Bulk Insert (в Postgres — copy_records_to_table, в OpenSearch — helpers.bulk).

    Осмысленность: Названия кафедр и предметов брать из заранее заданных списков-констант (не дефолтный Lorem Ipsum).

3. Безопасность (API Gateway)

    Gateway — это входная точка. Он должен проверять заголовок Authorization: Bearer <JWT>.

    Сам JWT не требует сложной авторизации: достаточно проверки валидности подписи секретным ключом.

    Если токен валиден — запрос проксируется в соответствующий сервис lab1, lab2 или lab3.

3. Алгоритмы Лабораторных работ

ЛР №1 (Топ-10 прогульщиков по теме):

    Найти lecture_ids в OpenSearch по ключевому слову.

    В Neo4j найти student_ids, которые должны были быть на этих лекциях.

    В PostgreSQL посчитать процент посещаемости (таблица attendance) для этих студентов.

    Обогатить данные именами из Redis и вернуть топ-10.

ЛР №2 (Вместимость аудиторий):

    В Neo4j найти все занятия курса за семестр и посчитать count(Students) для каждого занятия.

    В PostgreSQL подтянуть требования к оборудованию для этих лекций.

    Вернуть JSON с требуемой вместимостью и списком оборудования.

ЛР №3 (Аудит профильных часов):

    В Neo4j найти профильные курсы кафедры для конкретной группы.

    В PostgreSQL посчитать «прослушанные часы» (кол-во посещений * 2).

    В Redis забрать данные о принадлежности группы к институту/университету.
